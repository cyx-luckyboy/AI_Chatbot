> 版本：v20260530  
> 状态：已确认  
> 原产品：小猪 AI 助手（vchat / pig-ai-assistant）

---

## 第一章 功能概述

### 1.1 背景介绍

用户在使用 AI 助手时，经常需要记录会议、讲座、讨论等语音内容，并快速获得文字转写与结构化总结。参考「元宝」等产品的体验，希望在 vchat 中新增**会议记录**模块：支持长时间录音、实时语音转写、录音回放、AI 自动生成标题与总结，帮助用户高效沉淀会议内容。

原产品：小猪 AI 助手  
原产品 code：vchat  
新增功能：会议记录（Meeting Record）

### 1.2 与已有功能的关系

| 维度 | 关系说明 |
|------|----------|
| 语音输入（聊天框麦克风） | **独立**。聊天语音输入为短句识别、写入输入框；会议记录为长时间录音 + 实时转写 + 持久化存储，互不干扰 |
| 百度 ASR | **扩展**。现有 `baiduAsrMain.ts` 为短时 REST 识别；会议记录需新增**百度实时语音识别 WebSocket** 集成 |
| LLM 对话 | **复用**。总结与标题生成走现有 Provider 工厂 + 主进程流式 IPC，不新增厂商 |
| 本地存储 | **扩展**。IndexedDB（Dexie）新增会议相关表；音频文件存 `userData/meetings/` |
| 路由与导航 | **新增**。首页增加入口卡片，独立会议模块页面（列表 + 详情双栏布局） |
| 会议内容问答 | **不在第一版范围**。后续可基于转写文本扩展 RAG 问答 |

## 第四章 业务场景

### 4.1 新增场景说明

#### 4.1.1 场景一：开始会议录音并实时转写

1. 用户在首页点击「会议记录」入口卡片，进入会议模块
2. 点击「开始录音」，应用请求麦克风权限并开始录制
3. 录音过程中，界面实时显示转写文字（逐句追加）
4. 顶部显示录音计时器与录音状态指示
5. 用户点击「停止录音」，录音结束，音频与转写文本保存到本地

#### 4.1.2 场景二：录音结束后自动生成 AI 总结

1. 录音停止后，系统自动调用当前配置的 LLM
2. 基于完整转写文本生成：会议标题（可编辑）、概述段落、结构化小结（分节 + 要点列表）
3. 总结生成过程中显示加载状态；完成后在「AI 总结」Tab 展示
4. 若转写文本为空或 LLM 调用失败，给出明确错误提示，允许用户稍后重试

#### 4.1.3 场景三：查看历史会议与回放

1. 会议模块左侧（或列表区）展示历史会议记录，按时间倒序
2. 每条记录显示：标题、日期时间、时长
3. 点击某条记录，右侧详情区展示：音频播放器（含波形）、转写 Tab、AI 总结 Tab
4. 用户可编辑标题、删除记录

#### 4.1.4 场景四：百度 ASR 未配置

1. 用户未配置百度 ASR Key 时，进入会议模块或点击开始录音
2. 提示前往设置页配置百度语音识别 Key，并说明会议记录依赖该服务
3. 不允许在无 ASR 配置时开始录音（避免用户录完无法转写）

## 第五章 功能性需求

### 5.1 SNR001_首页入口

#### 5.1.1 需求描述

在首页新增「会议记录」入口卡片，点击进入会议模块独立页面。

#### 5.1.2 输入输出

- 输入：用户点击卡片
- 输出：导航至 `/meetings` 路由

#### 5.1.3 需求约束

- 卡片文案支持中英文 i18n
- 视觉风格与现有首页一致

---

### 5.2 SNR002_会议录音与实时转写

#### 5.2.1 需求描述

用户可开始/停止长时间会议录音；录音过程中通过百度实时语音识别 WebSocket 将语音转为文字并实时展示。

#### 5.2.2 输入输出

- 输入：麦克风音频流
- 输出：本地音频文件（WAV/WebM）、实时转写文本片段、完整转写文本

#### 5.2.3 需求约束

- 使用百度实时语音识别 API（WebSocket），复用现有 `baiduAsrApiKey` / `baiduAsrSecretKey` 配置项
- 单次录音**不限时长**（受本机磁盘空间与百度 API 配额限制）
- 主进程负责 WebSocket 连接与音频帧发送，避免渲染进程 CORS 限制
- 录音格式：16kHz 单声道 PCM（与现有 `wavEncode.ts` 规范一致）
- 网络中断时：提示用户，已录内容与已转写文本保留，允许停止并保存

#### 5.2.4 需求过程

```
用户点击「开始录音」
  → 检查麦克风权限 + 百度 Key 配置
  → 创建 MeetingRecord（状态：recording）
  → 启动 MediaRecorder + 主进程 WebSocket ASR
  → 音频帧 → 主进程 → 百度实时 ASR → 转写片段 IPC 回传 → UI 实时追加
用户点击「停止录音」
  → 关闭 WebSocket + 停止 MediaRecorder
  → 保存音频文件到 userData/meetings/{id}.wav
  → 更新 MeetingRecord（状态：transcribed）
  → 触发 SNR003 自动总结
```

---

### 5.3 SNR003_录音结束自动 AI 总结

#### 5.3.1 需求描述

录音结束后，自动调用用户当前选中的 LLM Provider，基于转写文本生成会议标题与结构化总结。

#### 5.3.2 输入输出

- 输入：完整转写文本
- 输出：
  - `title`：AI 生成的会议标题（字符串，用户可编辑）
  - `summaryOverview`：概述段落
  - `summarySections`：结构化小节数组（标题 + 要点列表）

#### 5.3.3 需求约束

- 使用现有 `createProvider` + 流式 IPC 机制
- 总结 Prompt 要求输出结构化 Markdown，便于解析渲染
- 转写文本过长时按现有 `helper.ts` 截断策略处理，或分段总结后合并（具体策略由架构设计确定）
- 总结失败时不阻塞录音保存；状态标记为 `summary_failed`，提供「重新生成」按钮

#### 5.3.4 需求过程

```
录音停止 → 转写完成
  → 主进程/渲染进程发起 summarize-meeting IPC
  → LLM 流式生成 → 解析标题 + 总结结构
  → 写入 MeetingRecord（状态：completed）
  → UI 切换至「AI 总结」Tab 展示
```

---

### 5.4 SNR004_会议详情与音频回放

#### 5.4.1 需求描述

选中某条会议记录后，展示详情页：顶部音频播放器（计时、波形、播放/暂停、倍速），下方 Tab 切换「实时转写」与「AI 总结」。

#### 5.4.2 输入输出

- 输入：MeetingRecord ID
- 输出：音频播放、转写全文、AI 总结内容

#### 5.4.3 需求约束

- 波形：基于音频振幅数据渲染，播放进度与波形联动
- 倍速：至少支持 0.5x / 1x / 1.5x / 2x
- 转写 Tab 展示完整转写文本，支持滚动定位（不要求词级高亮跟读，可作为后续增强）
- 布局参考元宝：左侧列表 + 右侧详情（响应式：窄屏可折叠列表）

---

### 5.5 SNR005_会议列表与管理

#### 5.5.1 需求描述

展示所有历史会议记录，支持选择、编辑标题、删除。

#### 5.5.2 输入输出

- 输入：用户操作（选择/编辑/删除）
- 输出：列表刷新、详情更新、本地文件与 DB 记录同步删除

#### 5.5.3 需求约束

- 列表按 `createdAt` 倒序
- 删除需二次确认
- 删除时同步删除 `userData/meetings/` 下对应音频文件

---

### 5.6 SNR006_标题编辑

#### 5.6.1 需求描述

AI 生成标题后，用户可在详情页或列表中点击编辑并保存。

#### 5.6.2 需求约束

- 标题最长 100 字符
- 空标题不允许保存，回退为时间戳默认名

## 第六章 非功能性需求

### 6.1 兼容性

- 不影响现有聊天语音输入、对话、设置等功能
- 百度 Key 配置项复用，设置页可增加「会议记录说明」提示
- Windows 10+ 为主要目标平台；麦克风权限遵循 Electron 标准流程

### 6.2 安全性

- 会议音频与转写文本仅存本机，不上传至除百度 ASR 与用户配置的 LLM 厂商以外的第三方
- 音频文件路径不暴露给渲染进程任意读写，通过 IPC + safe-file 协议访问

### 6.3 稳定性

- 长时间录音（1h+）内存占用可控：音频流式写盘，不全量驻留内存
- WebSocket 断线自动重连或 graceful 降级（保留已转写内容）
- 应用意外退出后，下次启动可检测未完成的录音会话并提示恢复或丢弃

### 6.4 性能

- 实时转写延迟：正常网络下 ≤ 3 秒（受百度 API 影响）
- 列表加载 100 条记录 < 500ms
- AI 总结时间与转写文本长度和 LLM 响应速度相关，UI 需有进度指示

## 第七章 风险分析

| NO | 风险项描述 | 影响度(I) | 概率(P) | 优先级 | 可能发生阶段 | 应对策略与措施 |
|----|-----------|-----------|---------|--------|-------------|---------------|
| R1 | 百度实时 ASR WebSocket 集成复杂度高于现有 REST 短时识别 | 高 | 中 | 高 | 开发 | 主进程封装独立模块；先用官方 Demo 验证连通性 |
| R2 | 长时间录音导致内存/磁盘压力 | 中 | 中 | 中 | 开发/使用 | 流式写盘；设置软提示（如超过 2h 提醒） |
| R3 | 百度 API 配额/计费超出用户预期 | 中 | 低 | 中 | 使用 | 设置页说明计费方式；录音前展示预估提示 |
| R4 | 转写文本过长导致 LLM 总结超限 | 高 | 中 | 高 | 开发 | 分段总结 + 合并，或截断 + 告知用户 |
| R5 | 麦克风权限被拒绝 | 中 | 低 | 低 | 使用 | 明确引导用户到系统设置开启权限 |
| R6 | 网络不稳定导致实时转写中断 | 高 | 中 | 高 | 使用 | 保留已转写内容；提示重连；允许停止并保存 |
