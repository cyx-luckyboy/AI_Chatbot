# 小猪 AI 助手 — 使用说明与代码导读

本文档面向：**日常怎么用软件**，以及：**代码大致分几块、各负责什么**。详细实现仍以源码为准。

---

## 一、软件操作说明

### 1.1 如何运行

| 场景 | 做法 |
|------|------|
| **开发调试** | 在项目根目录执行 `npm start`（Electron + Vite 热更新）。 |
| **绿色包** | 执行 `npm run package` 或 `npm run make:zip`，在 `out` 目录找到 Windows 文件夹或 zip，解压后运行其中的 exe。 |
| **安装包** | 执行 `npm run make`，使用生成的安装程序（Squirrel）。若安装失败，可优先用 zip 包；包名 `name` 需为英文（当前为 `pig-ai-assistant`）以利于安装器。 |

在浏览器里直接打开 Vite 地址时，**没有真实 Electron 能力**，界面能开但无法真正发起对话（由 `browserElectronShim.ts` 提供占位 API）。

### 1.2 主界面布局

- **左侧**：会话列表；顶部为 **应用名**、**搜索**（放大镜：匹配 **会话标题、当前模型名**，以及 **各条消息正文**（IndexedDB 全表扫描，输入防抖约 280ms））、**收起边栏**；底部 **「新建聊天」**、**「设置」**。收起侧栏后，主内容区顶栏左侧会出现 **展开边栏**、**新对话** 的紧凑按钮（不含搜索）。**搜索框有内容且搜索面板打开时**，主区域变为 **左：结果列表（摘要 + 高亮）**、**右：当前选中会话的元信息与命中消息片段**，并可 **进入对话**；此时侧栏内会话列表暂时隐藏以免重复。
- **右侧**：当前页内容（首页 / 某会话 / 设置）；顶栏右侧有 **当前定位**（如 `东莞 · 广东`，启动时自动获取）、**主题切换**、**「刷新」**。

### 1.2.1 「刷新」与路由

- 点击 **「刷新」** 会 **整页重载**（`location.reload`），用于打断卡住的流式回复或异常状态。
- 重载前会把当前路径写入 **`sessionStorage`**（键名见 `src/restoreRouteKey.ts`），`renderer.ts` 在挂载前读出并 **`router.replace`**，避免使用 **MemoryHistory** 时重载后总是回到首页。

### 1.3 新建对话与发消息

1. 点 **「新建聊天」** 进入首页，选择 **厂商与模型**（需先在设置里配置对应 Key）。
2. 在输入框输入文字，点 **发送** 或 **Enter**（**Shift+Enter** 换行）。
3. 回复以流式形式出现在对话区；出错时会有错误提示内容。

### 1.3.1 消息气泡下方操作

- **助手回复**（生成结束后）：复制、朗读（浏览器语音合成）、喜欢/不喜欢（写入本机 IndexedDB 字段 `feedback`）、**导出**（下拉：导出为 PNG 截图 / 导出为 `.md` 文档）、重新生成（删除本条及之后消息后重新请求模型）。
- **用户发送的消息**：**导出**（同上，截绿色气泡）、**引用**（将内容以 Markdown 引用块插入底部输入框，可继续编辑后发送）。

导出图片使用 **`html2canvas`** 截取气泡 DOM。

### 1.3.3 联网搜索（Tavily）

- 输入区工具栏可进入 **「联网搜索」** 模式，或发送 **天气、新闻、股价** 等时效问题时，在已配置 **Tavily API Key** 时会 **自动联网**。
- Key 填写位置：**设置 → 通用 → 联网搜索**，或在项目根目录 `.env` 中设置 `TAVILY_API_KEY`（可参考 `.env.example`）。
- 流程：主进程判断是否需要检索 → 调用 Tavily → 将摘要与来源注入上下文 → 模型流式回答；助手消息下方可展开 **参考来源** 列表并打开链接。
- 定位信息会用于优化检索关键词（如「今天天气」会带上当前城市）。

### 1.3.4 定位（自动）

- **无需在设置里配置**：应用 **启动时** 自动尝试 **Windows 本机定位**（需系统开启「位置服务」并允许桌面应用访问位置）；失败且尚未有城市时再回退 **IP 定位**。
- 右上角绿色标签显示当前城市/省份，悬停可查看说明。
- 每次对话请求会附带 **地理位置 system 上下文**（`userLocation.ts` / `chatSystemContext.ts`），便于回答本地天气、同城资讯等。
- **说明**：IP 定位在国内常误显示「北京」等枢纽城市；本机定位更准确。控制台若出现 Google `403`，多为浏览器定位备用路径，与本机 WinRT 定位无关。

### 1.3.2 模型与「当前时间」

- 界面上的消息时间戳来自本机数据库，**不会**自动告诉模型。
- 每次发起对话前，主进程会在请求中附加 **`system` 提示**（`src/chatClockContext.ts`），写入 **ISO 时间与本地时区格式化结果**，便于回答「今天是几号」等；**Claude** 路线会将该系统提示放进 Anthropic 的 **`system` 字段**（见 `ClaudeDirectProvider.ts`）。

### 1.4 图像生成、PPT 生成

- **图像生成**：输入区工具栏进入模式后，用自然语言描述画面；默认走 **即梦（火山引擎）**，需在设置或 `.env` 配置 `VOLC_ACCESSKEY` / `VOLC_SECRETKEY`；可选 OpenAI 兼容文生图（`IMAGE_GEN_BACKEND=openai`）。
- **PPT 生成**：输入大纲或主题，模型输出结构化 Markdown，主进程用 **pptxgenjs** 等生成 `.pptx` 并可另存到本机；支持多种版式/主题（见 `pptThemes.ts`、`pptLayouts.ts`）。

### 1.5 附件与图片

- 输入框旁 **「+」** 可添加 **文件或图片**（有数量与大小限制，以界面为准）。
- **小文件**（约 14MB 以内）可走 data URL 内联；**更大文件**（最大约 **50MB**）由主进程 **`import-user-attachment`** 复制到 `userData` 再按路径读取（见 `attachmentLimits.ts`）。
- 发送前附件会保存到本机应用数据目录（或浏览器预览环境下暂存为 **data URL**），主进程按路径 / 二进制内容读取后再拼进发给模型的上下文。

**各类型大致行为（主进程 `helper.ts` 的 `convertMessages`）：**

| 类型 | 处理方式 |
|------|----------|
| 常见纯文本后缀（如 `.txt`、`.md`、`.json`） | 按 UTF-8 读入正文（过长会截断）。 |
| **PDF** | 使用 **pdf-parse（v1，走 `lib/pdf-parse.js` 入口）** 抽取纯文本；扫描件/图片型 PDF 可能抽不到字；单文件约 **25MB** 上限。 |
| **Word（.docx）** | 使用 **mammoth** 抽取纯文本；**不支持旧版二进制 .doc**（请先在 Office/WPS 中另存为 `.docx`）；加密文档可能失败；单文件约 **25MB** 上限。 |
| **图片** | 读入后以 **base64** 作为 OpenAI 兼容的 `image_url` 传入；**需选用支持视觉/多模态的模型**（如通义 qwen-vl、GPT-4o 等），否则模型可能几乎不返回有效正文。用户消息内会尽量 **先图后文**；仅发图时会自动补一句占位说明。 |
| 其他未识别类型 | 不会内联全文，仅提示用户改传文本或说明需求。 |

**气泡里图片预览（Electron）：** 使用自定义协议 **`safe-file`**。URL 必须为 **`safe-file:///` + `encodeURIComponent(绝对路径)`**（三段斜杠），由主进程解析 `pathname` 后映射到本地文件；请勿在纯浏览器里依赖该协议（请用 `npm start` 跑桌面端）。

**说明：** 大模型 HTTP(S) 请求在 **主进程** 发出，在渲染进程 DevTools 的 **Network** 里往往**看不到**接口请求，属正常现象。

### 1.6 语音输入

- **已配置百度语音 Key**（设置 → 通用）：优先走 **百度短时识别**。流程为：**第一次点麦克风开始录音 → 说话 → 再点一次麦克风结束**，识别结果**追加到输入框**，**不会自动发送**，需自行点发送。
- **未配置百度**且系统支持 **Web Speech**：可 **连续听写、实时上屏**；在国内常因网络无法连上谷歌服务而失败，此时建议在设置中填写百度 Key。
- 麦克风、网络或密钥异常时，输入框下方会出现**提示文案**。

### 1.7 设置（「设置」页）

- **通用**：界面语言、字体大小、**百度语音识别** Key、**Tavily 联网搜索** Key（仅存本机 `config.json` / `.env`，勿提交到公开仓库）。**定位已改为启动自动获取**，设置页不再提供手动定位表单。
- **外观**：浅色/深色主题、聊天背景图等。
- **模型**：各厂商的 Key、Base URL 等，按表单项填写后**自动保存**。内置种子厂商包括（具体以界面为准）：**百度千帆**、**阿里灵积**、**DeepSeek**、**Claude**、**Kimi**、**小米 MiMo**、**MiniMax**、**ChatGPT（OpenAI 官方 API）** 等；部分厂商支持在设置中填写国内/国际不同 **Base URL**（详见各厂商占位说明）。

### 1.8 侧栏会话操作

- 会话项支持 **重命名**、**置顶**（置顶会话排在列表前）、**删除**（同时删除该会话消息）。

### 1.9 数据存在哪里

- **应用配置**：Electron `userData` 下的 `config.json`（语言、字体、各 Key 等）。
- **对话与消息、厂商列表**：浏览器侧 **IndexedDB**（Dexie，库名见 `db.ts`）。
- **用户图片 / 附件**：`userData` 下 `images`、`attachments` 等目录（由主进程 IPC 写入）。

### 1.10 窗口标题与图标

- 标题栏显示名由 **`src/appMeta.ts`** 中常量与主进程逻辑共同保证。
- 图标使用仓库根目录 **`pig.ico`**；打包配置见 **`forge.config.ts`**。

## 二、代码结构 — 各部分功能

> **目录约定（域分类、旁路语音服务、vendor）以 [`docs/overview.md`](./overview.md) 为准。** 下文为进程与职责摘要。

### 2.1 进程划分（Electron）

| 进程 | 目录 / 入口 | 职责摘要 |
|------|----------------|----------|
| **主进程** | `src/main/main.ts` | 创建窗口、系统菜单、`safe-file` 协议、加载页面；最早执行 `squirrel-startup`。 |
| **预加载** | `src/preload/preload.ts` | 安全桥接：把 IPC 封装成 `window.electronAPI`，类型在 `preload.d.ts`。 |
| **渲染进程** | `src/renderer/renderer.ts` → Vue | 全部 UI、路由、Pinia、Dexie 访问（IndexedDB）。 |

主进程与渲染进程通信集中在 **`src/ipc/setup.ts`**（`setupIPC` 在 `main/main.ts` 里调用）。业务按域放在 `src/domains/*`。

## 五、近期变更摘要（开发记录）

以下为近期迭代中与用户可见行为相关的主要改动，便于对照版本与排错：

- **侧栏与导航**：会话 **搜索**、**收起/展开**、收起态顶栏快捷入口；**整页刷新** 并 **恢复当前路由**（`restoreRouteKey` + `renderer` 挂载前 `replace`）。
- **消息气泡**：助手 **复制 / 朗读 / 喜欢·不喜欢 / 导出图片与 Markdown / 重新生成**；用户消息 **导出 / 引用到输入框**；导出截图依赖 **`html2canvas`**；Markdown 正文在 **深色模式** 下可读性修正。
- **模型时间**：主进程每次 `start-chat` 注入 **本地系统时间**（`chatClockContext.ts`）；Claude 将系统提示置于 API 的 **`system` 字段**。
